# 模板入库 QA 流程（TEMPLATE_ONBOARD_SOP）

> 适用：trade-docs-system（商单易）模板库任何新模板入库。2026-11-20 用户确认，全团队/全机器统一执行。
> 本文件随仓库同步；各机器拉取镜像后即持有最新版。

## 铁律
1. 每阶段产出可落盘验证产物，不允许"看起来对了"。
2. 字段映射表必须用户拍板后才进后续阶段。
3. userdata.json 注入前先与 GitHub main 比对（防覆盖）。
4. 部署后做运行时链路级验证（模拟 `_fetchTplFile` 逐模板验证 URL 200+逐字节一致；v1.8.1 教训：硬编码 id+'.xlsx' 曾致 5 份模板下载必失败）。
5. 部署完成立即发线上链接。
6. 保留回滚快照 `_rollback_版本_日期/`。

## 7 阶段
| 阶段 | 动作 | 产物 |
|---|---|---|
| 0 源文件盘点 | 模板族（原件/空白/变体）逐格 diff；多 sheet 清点 | diff 清单 |
| 1 空白模板体检 | 结构逐字比对；残留扫描（样张/测试垃圾）；必填与勾选框齐全 | 体检表（清除后 diff=空白版） |
| 2 位置映射 | 业务格→字段映射表；勾选控件映射 | 映射表（**用户拍板**） |
| 3 对比验证 | 按映射灌值回放 vs 已填版逐格 diff | 报告（覆盖100%/不一致0/遗漏0） |
| 4 模拟导出 | Node 全链路 buildDocData→导出；audit 六维；已知陷阱回归；真实案例回放 | 导出核验记录 |
| 5 部署验证 | 三关+徽标缓存参数；运行时链路验证 | 线上核验证据 |
| 6 交付闭环 | 模板档案归档；硬刷新提醒+发链接；回滚快照 | 档案 |

## 分层
- 仅下载填写类（kind=booking_word）：走 0/1/5/6。
- 自动填值类（kind=booking + preset）：走全 0-6。
